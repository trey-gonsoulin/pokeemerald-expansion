# Fork features

What the fork adds over upstream in the game itself: config flips, prize swaps and new features. See also `carried-fixes.md`, `debug-menu.md` and `balance.md`.

- Personal-playthrough config flips in `include/config/` (reusable TMs, Gen 6 Exp. Share on `FLAG_UNUSED_0x264`, followers, HGSS Pokédex, IV/EV summary, forgettable HMs).
  - QoL flips (#202): `B_QUICK_MOVE_CURSOR_TO_RUN`, `B_SHOW_PARTNER_TARGET` (with its carried fix in `carried-fixes.md`), `P_SHOW_DYNAMIC_TYPES`, `P_ASK_MOVE_CONFIRMATION`, `OW_POPUP_GENERATION` `GEN_5` (black, 12-hour clock; upstream's "Map names fit in popup" in `test/text.c` now checks the Gen 5 bar's font and width instead of assuming Gen 3), `OW_HIDE_REPEAT_MAP_POPUP` and `OW_BERRY_IMMORTAL`. The owner turned down `OW_SHOW_ITEM_DESCRIPTIONS`, `B_SHOW_TYPES`, `B_HP_PERCENTAGE_DISPLAY`, `B_FAST_INTRO_NO_SLIDE`, `TEXT_SPEED_INSTANT`, `AUTO_SCROLL_TEXT` and `P_ENABLE_MOVE_RELEARNERS`.
  - The DexNav (#203, `include/config/dexnav.h`): it unlocks with the Pokédex (`DN_FLAG_DEXNAV_GET` is `FLAG_SYS_POKEDEX_GET`) and uses `FLAG_UNUSED_0x021`/`0x022` and `VAR_UNUSED_0x40F7`/`0x40F8`. `USE_DEXNAV_SEARCH_LEVELS` puts one byte per species in SaveBlock3, which is then 1576 of its 1624 bytes (`test/save.c` pins it; old saves read the levels as 0). That leaves no room for `OW_ITEM_DESCRIPTIONS_FIRST_TIME`'s 110 bytes, and a large upstream species addition would trip the `src/save.c` assert. The fork has no `hidden_mons` tables, so detector mode does nothing.
    - The DexNav searches in a cave lit by Flash (#210, a fork change kept here rather than with the carried upstream fixes, since it changes what the search does: upstream said "It's too dark" at any `flashLevel` above 0, and Flash, or Flash's badge on entering a cave since #186, leaves 1, the 72 px circle around the player). `IsDexNavSearchTooDark` (`src/dexnav.c`) refuses only an unlit cave (`flashLevel` above 1). In the light, `DexNavPickTile` scans the circle instead of its usual area and puts the patch on any eligible tile wholly inside it (`IsDexNavTileLit`, from `GetFlashLevelRadius` in `src/field_screen_effect.c`): 3 tiles out in a line, up to (3, 2) diagonally, past the usual 2-tile gap.
      - The gap grows to 3 at search level 50 and up, where a cave or water Pokémon moves once the player is within 3 (`GetMovementProximityBySearchLevel`), so it doesn't move at once: `InitDexNavSearch` now sets `searchLevel` before the pick. That leaves 32 candidate tiles, or 20, before walls.
      - Upstream's per-tile chance (1 in about 100-250 in caves) is skipped there: it suits the usual 144-tile area, and on the circle most searches would find nothing.
      - Running (a 5-tile gap) or cycling (7) leaves no lit tile, so the search bails as with no tile ("not found nearby"). Every lit patch is within 5 tiles, so running toward it ends the search ("moved too fast") as soon as it is within 4, as upstream does near any patch.
    - With the Pokédex and the PokéNav the start menu has 9 entries, which ran past the bottom of the screen: `AddStartMenuWindow`, `src/menu.c`, caps the window at the 18 rows between the frames, and `GetStartMenuTextTop` drops the 9 px top margin for a menu that long (`src/start_menu.c`). No test.
    - In the debug ROM, R+Start always opens the debug menu (#210): `IsDexNavSearchButtonPressed`, `src/dexnav.c`, called from `FieldGetPlayerInput`, starts the search for the registered species on R's release instead of its press, and not at all if Start was pressed while R was held. It runs every field frame, so it sees Start and the release between tiles too (the search then starts at the next tile), and it drops the press when a script or battle takes the field before the release (`ArePlayerFieldControlsLocked`). The release ROM (no `DEBUG_OVERWORLD_MENU`) still searches on R's press, and LTO leaves no trace of the rest.
    - Covered by "DexNav:" in `test/dexnav.c`, which calls the search-level and chain functions, the darkness gate, the lit tiles and the R/Start rule directly; nothing covers the battle-outcome check that calls the first two (`src/battle_main.c`), the tile scan on a real map, the field input or the screen.
  - Trade evolutions solo (#208): `I_USE_EVO_HELD_ITEMS_FROM_BAG` (Metal Coat, King's Rock and the other trade items, plus Razor Claw, Razor Fang and Oval Stone, work from the bag like stones), and the Lilycove Department Store 3F vitamins clerk sells upstream's Linking Cord (8000) for the trades without a held item (`data/maps/LilycoveCity_DepartmentStore_3F/scripts.inc`).
